# 正式五级路网规划规范

本项目的地图不是“线路越多越好”，而是固定遵循由粗到细的交通层级。所有正式地图扩展必须继续满足该结构。

## 1. 高速 Hxx

- 只承担跨区主通道。
- 只连接道路枢纽，不直接把客运站当高速交叉口。
- 数量最少、线形最平顺、弯折半径最大。
- 全国缩放级别始终显示。
- 当前正式高速骨架固定为 6 条走廊：H01 / H02 / H03 / H11 / H13 / H21；走廊内部由多个 RoadSegment 连续组成。
- displayPriority 固定为 1；只有高速允许在全国总览直接显示。

## 2. 国道 Nxxx

- 连接主要城市、枢纽客运站和跨区次级通道。
- 国道 displayPriority 固定为 2，全国总览不显示；放大到区域级后出现。
- 不与高速完全重合，允许在相邻区域形成替代路线。
- N101–N104 与 N201–N202 都属于区域级道路，区别只在走向和承担的城市串联任务。

## 3. 省道 Pxxx

- 负责区域内部织网以及客运站到高速枢纽的接驳。
- 只在区域及更近缩放显示。
- 允许比国道更弯曲，但不得跨整张全国地图充当第二套国道。
- 高速接驳同样使用省道层，不把高速直接拉进每一个站点。

## 4. 县道 Cxxx

- 只解决县域、邻县、县城到附近城市的短距离连接。
- displayPriority 固定为 4。
- 不允许做跨区长通道，不允许与国道/省道重复占用同一对节点。
- 只有放大地图后才显示。

## 5. 乡道 Lxxx

- 只作为乡镇客运站、县级站周边的末端支线和局部小环。
- 可以出现短支路和局部绕行，但不能形成全国骨架。
- displayPriority 固定为 4.
- 最大缩放级别才完整显示。

## 视觉纪律

- 禁止横平竖直规则网格。
- 禁止为了“显得路多”重复连接同一对节点。
- 高速线形最顺，国道次之；省道、县道、乡道允许逐级增加弯曲。
- 西部路网更稀疏，东部/沿海与核心城市群更密。
- 全图只看高速、主国道和枢纽站；区域级增加次级国道、省道；近景才显示县乡道。
- 道路编号属于地图内容元数据，不进入 Finance / Trip / Vehicle 等核心业务状态。

## 路网结构

- 长距离道路必须由多个正式节点和多个 RoadSegment 组成，禁止“一根线跨几百公里”。
- 重点枢纽城市建立独立环线节点与环线道路，客运站通过城市接驳路接入环线。
- 高速互通、城市环线互通、区域路口都是正式 junction 节点。
- 不同等级道路不得重复占用同一对端点；已有高等级通道时，低等级道路必须绕行、分叉或停止延伸。
- 展示层使用平滑曲线，但寻路仍严格沿正式 RoadSegment / polyline 运行。

## 四级显示

- Level 0：高速 + 枢纽站。
- Level 1：增加国道 + 市级站。
- Level 2：增加省道 + 县级站。
- Level 3：增加县道 / 乡道 + 乡镇站。

RoadNetworkStyleValidator` 会在 Core Check 和 APK 构建前阻止道路编号错级、重复端点、高速直连普通站、县乡道过长、显示优先级错配等问题进入正式版本。


## 道路结构角色

每条正式道路除 roadClass 外，还必须有 roadRole：

- mainline：高速/国道等连续主线。
- urban_ring：城市外围环线，省道等级、Level 2 后出现。
- connector：主路到城市环线/客运站周边的接驳线。
- ramp：互通匝道，只允许 local + displayPriority 4，单段不得超过 100km。
- local_access：县乡道路或站点末端接入。

起步样板区的 H02/H21 已使用独立主线节点 + 6 段匝道实现立体互通，不允许恢复成共享十字节点。

## 导航地图式渲染规则

- 正式 RoadSegment 仍是寻路与车辆运行的唯一事实来源。
- 同一 roadCode 的连续 RoadSegment 在展示层必须先拼成 corridor，再作为一条连续道路走廊绘制；禁止每段单独画成折线。
- 道路统一采用“道路边缘 + 浅色路面”双层结构。道路等级主要通过边缘宽度、编号牌和 LOD 区分，而不是五种完全不同的高饱和颜色。
- 所有道路边缘先绘制，再绘制共享 junction 路面补片，最后绘制道路表面。这样共享节点会自然形成汇入/分叉口，不出现多条彩线硬碰。
- 非共享节点的几何交叉不生成 junction 补片，从视觉上保留跨线/跨越关系。
- roadCode 用导航式盾牌显示，不使用散落的纯文本编号。
- 默认打开地图使用区域级视角；全国总览仍可通过“全图”按钮查看。
- junction 只用于路网结构，不在全图绘制黑色圆点；近景只保留必要的互通融合效果。


## 国内道路网形态参考规则

起步区域不再使用规则网格。后续扩展统一参考国内真实公路网的组织逻辑，但继续使用架空城市与道路编号。

- 高速走廊按地形和城市外围自然弯曲，不允许用等距水平线/垂直线铺满地图。
- 两条高速相交时优先错位互通、斜交互通或匝道转换，不使用简单十字节点表示大型互通。
- 城市外环必须是不规则多节点环或半环，禁止用 N/E/S/W 四个等半径节点组成方框。
- 国道允许和高速大致平行，但必须承担不同城镇串联任务，不得贴着高速重复描线。
- 省道负责城市群内部连接，路线应根据城市、河流、山地间隙自然弯曲。
- 县乡道路只在近景展开，形成自然分叉和局部连通，不做棋盘式补格。
- 同一走廊至少使用多个 polyline 控制点；重要走廊不能退化为两点直线。
- 默认城市群视角隐藏县乡道路与匝道，继续放大后再显示细路网。

## 地图城市与运营线路表现

- 道路底图统一使用绿色系道路边缘 + 浅色路面，禁止恢复高饱和蓝色高速。
- 城市/客运站按 stationClass 四级显示：
  - hub：最大标记 + 外圈；
  - city：中大型；
  - county：小型；
  - town：最小。
- WorldMapStationContent.unlockReputationPermille 是正式地图解锁门槛。
- 未解锁城市仍出现在地图上，但灰显并带锁；线路创建下拉框只列出已解锁城市。
- 当前 180/1000 声誉下固定应有 12 个城市/站点解锁。
- 地图页画布应尽量占满 header 与底部时间控制条之间的可用高度，不再保留大面积纯黑空白。
- 玩家自建 PassengerRoute 必须沿 route.pathLegs 的正式道路几何渲染，使用暖色 route overlay，不允许另画一条与寻路无关的装饰直线。


## 道路美术渲染规范

- 路网拓扑与道路美术分离。美术升级不得修改正式寻路节点或 RoadSegment。
- 每条道路按四层绘制：
  1. road-shadow：低透明度柔和外轮廓；
  2. road-casing：道路等级边缘；
  3. road：统一米白色路面；
  4. road-detail：仅近景高速/国道显示的细节线。
- 高速、国道、省道、县道、乡道使用同一绿色体系，通过宽度、饱和度、LOD 和路牌区分，禁止恢复蓝色高速或策略图式彩色线。
- 全图缩放时高速自动减薄并隐藏路牌/细节，避免道路压住城市和地形。
- 区域缩放后逐步恢复国道、省道和正常线宽。
- 最靠近视角才显示高速/国道内部细节线，县乡道继续保持轻量。
- junction 只负责填补道路接口缝隙，不得画成可见的黑点或大圆节点。
- 匝道必须比主线更细，城市环线低于高速主线但高于普通省道。
- 玩家运营线路始终覆盖在道路表面之上，使用暖色，不能与底图道路共用绿色。

## 道路视觉母版 V3

本节冻结地图母版第2步的正式道路视觉，后续只能在此基础上微调，禁止重新回到单一绿调或高饱和策略图配色。

### 正式色阶
- 高速：深玉绿边框（主色约 #0A8E74）+ 暖白路面。
- 国道：低饱和朱红边框（主色约 #C66B56）+ 暖白路面。
- 省道：灰金绿边框（主色约 #9A9C73）+ 暖白路面。
- 县乡道：灰绿边框（主色约 #9CA9A2 / #B8C0BB）+ 暖白路面。
- 玩家运营线路：高亮橙色，必须压在底图道路之上。

### 缩放规则
- 全国级 Level 0：只显示高速；高速自动减薄，隐藏道路编号牌和内部细节。
- 区域级 Level 1：显示高速 + 国道；高速、国道使用中等线宽。
- 城市群 Level 2：增加省道，恢复主干道正常宽度。
- 近景 Level 3：显示县乡道、匝道、接驳；高速/国道才显示 road-detail 内部细节线。

### 高速显示纪律
- 高速在远景不得用与近景相同粗度，避免形成“粗方块/绿色管线”。
- 高速 junction 在远景只承担连续路面融合，不显示明显节点圆。
- 匝道始终比高速主线细，只有近景完整出现。
- 高速编号牌全国视角隐藏，避免和城市标签争抢视觉。
- road-detail 只在近景出现，禁止全国视角显示中轴细节。

### 路网层次
- road-shadow 只提供轻微抬升，不承担道路识别。
- road-casing 承担等级与色彩识别。
- road surface 统一暖白，保证视觉一致。
- road-detail 只服务近景高速/国道，不增加新的寻路或业务数据。


## 城市标签与运营线路母版 V1

### 城市标签
- 标签布局按 hub → city → county → town 的优先级依次占位。
- 同级情况下优先已解锁城市，未解锁城市不得抢占主要视觉位置。
- 标签候选位置依次尝试右上、左上、右下、左下、正上、正下。
- 标签需要明显偏移时允许显示短引线，禁止直接压住站点圆点或主要线路牌。
- 未解锁站点与标签降低不透明度，但仍保留地图空间认知。

### 玩家运营线路
- 玩家线路永远绘制在底图道路之上、城市标记之下或同层明确分离。
- 路线使用暖色系轮换：橙 / 金 / 珊瑚橙 / 琥珀，不能与道路等级颜色混淆。
- 多条线路共用相同道路时允许 ±4.4px 范围内轻微平行偏移，不允许随线路数量无限外扩。
- 每条激活线路在首末站显示小型端点环。
- 线路牌优先放在路径中部；若与城市标签碰撞，依次尝试上下、左右和斜向偏移。
- 路线显示仍严格来源于 PassengerRoute.pathLegs → RoadSegment.polyline，不允许创建独立装饰路径。


## 正式地形底图

- 正式底图资源：presentation/apk/assets/map/base-terrain.webp。
- 运行资源尺寸：2896 × 2172，4:3，与地图 1100 × 825 viewBox 同比例。
- 底图通过 SVG <image> 放入地图坐标系，不使用 CSS 固定背景，因此拖动和缩放必须与道路、城市、线路完全同步。
- 删除旧 terrainMountain / terrainHill / terrainRiver / terrainLake / terrainCoast 程序占位层。
- 底图只承担地形背景；道路、城市、玩家线路仍由正式矢量数据绘制在其上。
- 最大放大由 mapCamera.w >= 0.25 * world viewBox 限制。2×底图在该倍率下仍保留足够像素密度，禁止恢复无限放大导致明显像素化。
- APK 构建必须检测 base-terrain.webp 存在，并复制 presentation/apk/assets 到 www/assets；资源缺失时构建直接失败。


## 地图 LOD 与瓦片系统 V1

- 唯一地图展示配置：presentation/apk/map-view.v1.json。
- 该配置同时控制 viewBox、摄像机默认/最大放大、四级 LOD、底图校准和瓦片金字塔。
- 禁止在 HTML 与构建脚本中分别维护另一套独立阈值。

### 四级 LOD
- Level 0 / detail 0：camera ratio >= 0.72，全国级，只保留高速和最高级城市。
- Level 1 / detail 1：camera ratio >= 0.48，区域级，增加国道和普通城市。
- Level 2 / detail 2：camera ratio >= 0.30，城市群级，增加省道和县城。
- Level 3 / detail 3：camera ratio < 0.30，近景级，增加县乡道路、匝道、乡镇和 road-detail。

### 底图瓦片金字塔
- z0：1 × 1，724 × 543，总览使用。
- z1：2 × 2，整体 1448 × 1086，区域级使用。
- z2：4 × 3，整体 2896 × 2172，城市群与近景使用。
- 总瓦片数固定为 17。
- APK 构建时由正式 base-terrain.webp 自动生成瓦片，不在仓库维护第二套手工瓦片。
- 运行时只挂载当前摄像机覆盖范围及一圈缓冲瓦片，拖动进入新格子时才替换 SVG image。
- 瓦片边缘使用轻微 overlap，避免 WebView 亚像素采样产生白缝。

### 对位与校准
- terrain.calibration.offsetX / offsetY / scaleX / scaleY 是唯一底图对位参数。
- 默认值为 0 / 0 / 1 / 1，表示底图完整覆盖 1100 × 825 viewBox。
- 后续山脉、河流、海岸与路网需要微调时，只允许调整 calibration，不修改道路世界坐标来迁就背景。
- 1100 × 825 viewBox 与 2896 × 2172 底图保持严格 4:3 比例。


## 地图运行时容错

- Android WebView 不再运行时 fetch map-view.v1.json；APK 构建阶段将同一正式配置 JSON 直接注入 index.html。
- map-view.v1.json 仍保留在 APK 中作为调试/检查资源，但不是运行时依赖。
- base-terrain.webp 不再从 APK 生成目录删除，作为瓦片加载失败时的唯一兜底。
- terrainTiles 正常加载后隐藏 fallback；任一瓦片加载失败时恢复 fallback，禁止出现透明/空白地图块。
- 构建必须逐张确认 17 个瓦片文件存在，同时确认 fallback 整图存在。
- 模板必须保留 __MAP_VIEW_CONFIG_JSON__ 构建占位符；正式 APK 中该占位符必须被完全替换。


## 参考图高速路网 V1

本节冻结 0.19.7 接入的正式高速骨架。参考图只作为视觉与几何母版，游戏运行时仍使用正式 WorldMap RoadSegment 数据，不使用截图或图片道路参与寻路。

### 骨架结构
- H01：北部自然弧形跨区走廊。
- H02：河源—永安—云州一线的中部主客运走廊。
- H03：南部沿海/南缘自然走廊。
- H11：西部纵向/弧形联络高速。
- H21：中央斜向联络高速。
- H13：东部沿海弧形联络高速。
- 34 个 expressway RoadSegment ID 全部复用；不存在旧高速与新高速并行实现。

### 几何纪律
- 所有正式高速段至少使用 7 个 polyline 控制点。
- 任何高速段的起终节点都不得重新退化为严格水平或严格垂直的方格段。
- 三条横向主走廊允许明显高低起伏和弧形绕行，禁止等距平行。
- 纵向/斜向联络必须错位接入，不允许形成矩形网格。
- 新高速互通节点位置变更时，与之相连的省道 connector 和 local ramp 必须同步重接，禁止保留旧接口。

## 地图线路规划交互 V1

- “新建线路”主入口固定在地图页，不再以线路页下拉框作为主交互。
- 点击站点必须读取正式 stations/unlock 状态；未解锁站点只能查看解锁条件，不能加入线路。
- 玩家在地图上分别设置始发站和终点站。
- 两个站点选择完成后，必须调用 PlayableClient.previewRoute()。
- previewRoute() 必须复用 buildOfficialRoutePath(..., "fastest_time", ...)；禁止 UI 自己连直线或维护第二套寻路逻辑。
- 预览路径以黄色虚线显示，正式已开通线路继续使用暖色实线。
- 预览返回距离、预计纯道路行驶时间及各道路等级里程。
- 创建确认后调用正式 route.create + route.activate；预览与创建后的 pathPoints 必须完全一致。
- 多点线路以后扩展时仍沿用 orderedStationIds / RoutePathService，不增加 UI 独立 path 数据。

  - y = 250–1120km；

  - x >= 1300km 时 y >= 280km。
